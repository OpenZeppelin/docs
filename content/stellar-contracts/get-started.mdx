OpenZeppelin's Stellar library gives you audited Soroban building blocks: tokens, access control, smart accounts,
the confidential token, governance and more. This page points you to the right starting place for what you want to
build, then walks you through setting up, building and deploying your first contract.

## Start Building

production.

## Prototype or production?

**Prototyping or building an MVP.** Use the library and its examples as they are, on testnet. Client tools that are
still in development, such as the [Confidential Token SDK](https://github.com/brozorec/stellar-confidential-token-sdk),
are fine for demos. [Build with the SDK](/stellar-contracts/tokens/confidential/build-with-the-sdk) and
[Agent Wallet](/stellar-contracts/accounts/agent-wallet) are complete flows that have been run on testnet.

**Going to production.** Rely on audited pieces and close the gaps around them:

- Check the [audit reports](https://github.com/OpenZeppelin/stellar-contracts/tree/main/audits) for what each release
  covers. The examples are starting points, not production deployments.
- Pin exact versions, and don't use anything older than `0.7.3`
  ([advisory](https://github.com/OpenZeppelin/stellar-contracts/security/advisories/GHSA-jpg9-m7w4-c7wc)).
- Smart accounts: v0.8.0 changed the digest that signers commit to. Use a client that supports the version you deploy.
- Confidential token: holders need a client that builds proofs. The available SDK is unaudited, so plan for a reviewed
  client before handling real funds.

## Set up your environment

1. Install Rust and add the Soroban target:

   ```bash
   rustup target add wasm32v1-none
   ```

2. Install the [Stellar CLI](https://developers.stellar.org/docs/tools/cli/install-cli), version **25.2.0 or later**. Contracts built with soroban-sdk 28 need `stellar contract build`; plain `cargo build --target wasm32v1-none` fails.

## Add the library

Pin exact versions. The library iterates quickly, and minor versions can include breaking changes.

```toml
[dependencies]
soroban-sdk = "=28.0.0"
stellar-tokens = "=0.8.0"
stellar-access = "=0.8.0"
stellar-macros = "=0.8.0"
```

Add only the crates your contract uses: `stellar-accounts`, `stellar-confidential`, `stellar-contract-utils`, `stellar-fee-abstraction` and `stellar-governance` are also available.

Add a release profile too. `stellar contract build` refuses to build without `overflow-checks = true`; this is the profile the library itself uses:

```toml
[profile.release]
opt-level = "z"
overflow-checks = true
debug = 0
strip = "symbols"
debug-assertions = false
panic = "abort"
codegen-units = 1
lto = true
```

## Build and deploy to testnet

```bash
stellar contract build
stellar keys generate alice --network testnet --fund
stellar contract deploy \
  --wasm target/wasm32v1-none/release/<your_crate>.wasm \
  --source alice --network testnet \
  -- <constructor arguments>
```

For complete, deployable contracts, see the [examples](https://github.com/OpenZeppelin/stellar-contracts/tree/main/examples) in the library repository. Each one builds with `stellar contract build`.
