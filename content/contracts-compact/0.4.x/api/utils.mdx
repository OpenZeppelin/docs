- [EvmAbi](#EvmAbi): Ethereum ABI word encoding, for messages that must hash identically in Compact and on the EVM.

#### zeroAccount [toc] [#Utils-zeroAccount]
#### [!toc] [#Utils-zeroAccount]
<APIItemCompact
  circuitSig='zeroAccount() → Either<Bytes<32>, ContractAddress>'
  kind="pure"
  modulePrefix="Utils"
>
  Returns the canonical zero `Either<Bytes<32>, ContractAddress>` value: the
  left variant (`Bytes<32>`) set to zero. Used as the sentinel for mint/burn operations
  (a zero `from` signals a mint, a zero `to` signals a burn) and for cleared approvals.

  The left variant is chosen so that [isTargetZero](#Utils-isTargetZero) checks against `default<Bytes<32>>`,
  and to avoid triggering contract-address guards (e.g. circuits that check `!to.is_left`
  before delegating to an `_unsafe` variant). A right variant with `default<ContractAddress>`
  would also pass [isTargetZero](#Utils-isTargetZero), but the left variant keeps guards and error messages consistent.
</APIItemCompact>

#### computeAccountId [toc] [#Utils-computeAccountId]
#### [!toc] [#Utils-computeAccountId]
<APIItemCompact
  circuitSig='computeAccountId(secretKey: Bytes<32>) → Bytes<32>'
  kind="pure"
  modulePrefix="Utils"
>
  Computes an account identifier without on-chain state, allowing a user to derive
  their identity commitment before submitting an operation.

  <Callout type='warn'>
    OpSec: The `secretKey` parameter is a sensitive secret. Mishandling it can
    permanently compromise the security of this system:

    * **Never log or persist** the `secretKey` in plaintext — avoid browser devtools,
    application logs, analytics pipelines, or any observable side-channel.
    * **Store offline or in secure enclaves** — hardware security modules (HSMs),
    air-gapped devices, or encrypted vaults are strongly preferred over hot storage.
    * **Use cryptographically secure randomness** — generate keys with `crypto.getRandomValues()`
    or equivalent; weak or predictable keys can be brute-forced to reveal your identity.
    * **Treat key loss as identity loss** — a lost key cannot be recovered.
    * **Avoid calling this circuit in untrusted environments** — executing this in an
    unverified browser extension, compromised runtime, or shared machine may expose
    the key to a malicious observer.

    ## ID Derivation
    `accountId = persistentHash(secretKey)`
  </Callout>

  The absence of a domain-separation tag is DELIBERATE. This identifier
  is global by design: the same key material yields the same identity in
  every module deriving one, so a user who wishes to carry one identity
  across modules can. Modules wanting a per-deployment, unlinkable identity
  should not use this circuit.

  NOT FOR PRIVATE DERIVATION. This returns an identifier, not a secret,
  and the construction is untagged. A circuit deriving a PRIVATE value from a
  secret MUST use its own domain-separation tag.
</APIItemCompact>

#### uint8Word [toc] [#EvmAbi-uint8Word]
#### [!toc] [#EvmAbi-uint8Word]
<APIItemCompact
  circuitSig='uint8Word(value: Uint<8>) → Bytes<32>'
  kind="pure"
  complexity="k=6, rows=55"
  modulePrefix="EvmAbi"
>
  Encodes a `Uint<8>` as an `abi.encode(uint8)` word: the
  value in the least significant byte, zero elsewhere.

  This is also how a Compact `enum` should reach a digest, matching Solidity,
  where an enum ABI-encodes as its `uint8` ordinal: `uint8Word(kind as Uint<8>)`.
</APIItemCompact>

#### uint128Word [toc] [#EvmAbi-uint128Word]
#### [!toc] [#EvmAbi-uint128Word]
<APIItemCompact
  circuitSig='uint128Word(value: Uint<128>) → Bytes<32>'
  kind="pure"
  complexity="k=12, rows=2503"
  modulePrefix="EvmAbi"
>
  Encodes a `Uint<128>` as an `abi.encode(uint256)` word: the
  value big-endian in the low 16 bytes, zero-padded on the left.

  Costs roughly twice [uint64Word](#EvmAbi-uint64Word), so prefer the narrower
  encoder when the value fits in 64 bits.
</APIItemCompact>
