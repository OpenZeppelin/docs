#### approve [toc] [#NonFungibleToken-approve]
#### [!toc] [#NonFungibleToken-approve]
<APIItemCompact
  circuitSig='approve(to: Either<Bytes<32>, ContractAddress>, tokenId: Uint<128>) → []'
  kind="circuit"
  complexity="k=13, rows=3415"
  modulePrefix="NonFungibleToken"
>
  Gives permission to `to` to transfer `tokenId` token to another account.
  The approval is cleared when the token is transferred.

  Only a single account can be approved at a time, so approving the zero value clears previous approvals.

  In the case of an external (non-contract) caller, the caller's identity is derived from the [wit_NonFungibleTokenSK](#NonFungibleToken-wit_NonFungibleTokenSK)
  witness as `persistentHash(secretKey)`.

  Requirements:

  - The contract is initialized.
  - The caller must either own the token or be an approved operator.
  - `tokenId` must exist.
</APIItemCompact>

#### transferFrom [toc] [#NonFungibleToken-transferFrom]
#### [!toc] [#NonFungibleToken-transferFrom]
<APIItemCompact
  circuitSig='transferFrom(fromAddress: Either<Bytes<32>, ContractAddress>, to: Either<Bytes<32>, ContractAddress>, tokenId: Uint<128>) → []'
  kind="circuit"
  complexity="k=13, rows=4739"
  stackParams="true"
  modulePrefix="NonFungibleToken"
>
  Transfers `tokenId` token from `fromAddress` to `to`.

  <Callout type='info'>
    Transfers to contract addresses are currently disallowed until contract-to-contract interactions
    are supported in Compact. This restriction prevents assets from being inadvertently locked in contracts that cannot
    currently handle token receipt.

    In the case of an external (non-contract) caller, the caller's identity is derived from the [wit_NonFungibleTokenSK](#NonFungibleToken-wit_NonFungibleTokenSK)
    witness as `persistentHash(secretKey)`.
  </Callout>

  Requirements:

  - The contract is initialized.
  - `fromAddress` is not zero.
  - `to` is not zero.
  - `to` is not a ContractAddress.
  - `tokenId` token must be owned by `fromAddress`.
  - If the caller is not `fromAddress`, it must be approved to move this token by either [approve](#NonFungibleToken-approve) or [setApprovalForAll](#NonFungibleToken-setApprovalForAll).
</APIItemCompact>

#### _unsafeApprove [toc] [#NonFungibleToken-_unsafeApprove]
#### [!toc] [#NonFungibleToken-_unsafeApprove]
<APIItemCompact
  circuitSig='_unsafeApprove(
    to: Either<Bytes<32>, ContractAddress>,
    tokenId: Uint<128>,
    auth: Either<Bytes<32>, ContractAddress>,
    isExistenceRequired: Boolean
  ) → []'
  kind="circuit"
  complexity="k=11, rows=1870"
  stackParams="true"
  modulePrefix="NonFungibleToken"
>
  Approve `to` to operate on `tokenId`, requiring the token to exist
  only when `isExistenceRequired` is true.

  <Callout type='warn'>
    Passing false skips the check that `tokenId` was minted. Both
    [_unsafeTransferFrom](#NonFungibleToken-_unsafeTransferFrom) and `_update` read that invariant back, so a planted approval
    can mint a token nobody authorized or outlive a later mint. Pass false only where
    the owner has already been read, as `_update` does.
  </Callout>

  Counterpart to Solidity's `_approve(to, tokenId, auth, bool emitEvent)`, where
  the flag also suppresses the `Approval` event. Compact has no events, so it carries
  the existence check alone.

  Requirements:

  - The contract is initialized.
  - `tokenId` must exist, unless `isExistenceRequired` is false and `auth` is zero.
  - If `auth` is non 0, then this function will check that `auth` is either the owner of the token,
  or approved to operate on the token (by the owner).
</APIItemCompact>
