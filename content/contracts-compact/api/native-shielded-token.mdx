---
title: NativeShieldedToken API
---

This module provides the full NativeShieldedToken module API: the two token flavors, their shared core,
the supply and derived-nonce extensions, and the owner-gated preset.

<Callout type='info'>
  For an overview of the modules, read the [NativeShieldedToken guide](../native-shielded-token).
</Callout>

The page covers the following modules:

- **Token modules**
  - [NativeShieldedToken](#NativeShieldedToken): a single token type issued and burned by the contract.
  - [NativeShieldedTokenFamily](#NativeShieldedTokenFamily): many token types, keyed by domain, under one contract.
  - [NativeShieldedTokenCore](#NativeShieldedTokenCore): the shared core behind the two flavors; not composed directly.
- **Extensions**
  - [NativeShieldedTokenPublicSupply](#NativeShieldedTokenPublicSupply): on-chain minted and burned totals for a `NativeShieldedToken`.
  - [NativeShieldedTokenFamilyPublicSupply](#NativeShieldedTokenFamilyPublicSupply): per-domain on-chain totals for a `NativeShieldedTokenFamily`.
  - [NativeShieldedTokenPublicSupplyCore](#NativeShieldedTokenPublicSupplyCore): the shared core behind the two supply extensions; not composed directly.
  - [NativeShieldedTokenDerivedNonce](#NativeShieldedTokenDerivedNonce): mint coin nonces derived from a counter.
- **Preset**
  - [ZOwnableNativeShieldedToken](#ZOwnableNativeShieldedToken): a single token whose `ZOwnablePK` owner mints and burns, with a public minted total.

These modules export no structs or enums of their own. Coins are the standard library's `ShieldedCoinInfo`
(a `nonce`, `color`, and `value`) and `QualifiedShieldedCoinInfo` (the same plus the Merkle-tree index `mt_index`
of a coin the contract holds).

#### _mint [toc] [#NativeShieldedToken-_mint]
#### [!toc] [#NativeShieldedToken-_mint]
<APIItemCompact
  circuitSig='_mint(
    recipient: ZswapCoinPublicKey,
    amount: Uint<64>,
    nonce: Bytes<32>
  ) → ShieldedCoinInfo'
  kind="circuit"
  complexity="k=14, rows=10473"
  modulePrefix="NativeShieldedToken"
  stackParams="true"
>
  Mints `amount` of the token to `recipient`, using a
  caller-supplied nonce.

  The caller is fully responsible for nonce uniqueness. Reusing a
  nonce for the same (value, recipient) produces a duplicate commitment,
  which the protocol rejects. With a secret random nonce this is the
  recipient-private mint. For mints that require no caller-managed nonce,
  compose the `NativeShieldedTokenDerivedNonce` extension and pass its
  `_deriveNonce()` output.

  The returned coin info is the only copy available to the
  recipient; callers SHOULD deliver it out of band. Wallets cannot detect
  contract-minted coins by scanning the chain.

  Requirements:

  - Contract is initialized.
  - `recipient` is not zero.
</APIItemCompact>

#### _mintToSelf [toc] [#NativeShieldedToken-_mintToSelf]
#### [!toc] [#NativeShieldedToken-_mintToSelf]
<APIItemCompact
  circuitSig='_mintToSelf(amount: Uint<64>, nonce: Bytes<32>) → ShieldedCoinInfo'
  kind="circuit"
  complexity="k=14, rows=16070"
  modulePrefix="NativeShieldedToken"
>
  Mints `amount` to this contract itself, claiming the coin in
  the same call. Forwards to `NativeShieldedTokenCore._mint` with
  `right(kernel.self())`.

  Nonce uniqueness is the caller's responsibility, as in `_mint`. Spend
  the coin later with `_burnFromSelf`, once it carries an `mt_index`.

  The consumer SHOULD persist the returned coin info in its own
  ledger state: it is the contract's holding and is not otherwise
  recoverable.

  Requirements:

  - Contract is initialized.
</APIItemCompact>

#### _burn [toc] [#NativeShieldedToken-_burn]
#### [!toc] [#NativeShieldedToken-_burn]
<APIItemCompact
  circuitSig='_burn(
    coin: ShieldedCoinInfo,
    amount: Uint<128>,
    refundTo: ZswapCoinPublicKey
  ) → Maybe<ShieldedCoinInfo>'
  kind="circuit"
  complexity="k=16, rows=41492"
  modulePrefix="NativeShieldedToken"
  stackParams="true"
>
  Burns `amount` from `coin`, a coin provided within the
  current transaction (e.g. paid in by the caller's wallet), and routes the
  remaining change to `refundTo`.

  To destroy `coin` in full, pass `coin.value` as `amount`; the change
  branch will not fire and `none` is returned. The `refundTo` value is
  inert in that case but must still be supplied and non-zero.

  The coin is received by the contract and spent in the same
  transaction, so the spend goes through `sendImmediateShielded` (the
  transient path). For coins the contract already holds, use
  `_burnFromSelf` instead.

  The returned refund coin info is the only copy available to
  `refundTo`; callers SHOULD deliver it out of band. Wallets cannot detect
  contract-sent coins by scanning the chain.

  Requirements:

  - Contract is initialized.
  - `coin.color` is this contract's token color.
  - `amount` is less than or equal to `coin.value`.
  - `refundTo` is not zero (the zero key is the burn address; a zero
    `refundTo` would silently burn the change as well).
</APIItemCompact>

#### [!toc] [#NativeShieldedToken-_burnFromSelf]
<APIItemCompact
  circuitSig='_burnFromSelf(coin: QualifiedShieldedCoinInfo, amount: Uint<128>) → Maybe<ShieldedCoinInfo>'
  kind="circuit"
  complexity="k=15, rows=23307"
  modulePrefix="NativeShieldedToken"
>
  Burns `amount` from `coin`, a coin this contract already
  holds (a Merkle-tree entry with a valid `mt_index`). Any change is
  auto-received by the contract and returned.

  The consumer SHOULD persist the returned change coin info in its own
  ledger state: the change replaces `coin` as the contract's holding, and
  its info is not otherwise recoverable.

  Requirements:

  - Contract is initialized.
  - `coin.color` is this contract's token color.
  - `amount` is less than or equal to `coin.value`.
</APIItemCompact>

  Burns `amount` from `coin`, a coin provided within the
  current transaction (e.g. paid in by the caller's wallet), and routes the
  remaining change to `refundTo`.

  transaction, so the spend goes through `sendImmediateShielded` (the

  `receiveShielded` in this same call.

  `refundTo`; callers SHOULD deliver it out of band. Wallets cannot detect
  contract-sent coins by scanning the chain.

  - `amount` is less than or equal to `coin.value`.
  - `refundTo` is not zero (the zero key is the burn address; a zero
