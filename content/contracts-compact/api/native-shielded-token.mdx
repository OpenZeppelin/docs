title: NativeShieldedToken API
---

This module provides the full NativeShieldedToken module API: the two token flavors, their shared core,
the supply and derived-nonce extensions, and the owner-gated preset.

<Callout type='info'>
  For an overview of the modules, read the [NativeShieldedToken guide](../native-shielded-token).
</Callout>

The page covers the following modules:

- **Token modules**
  - [NativeShieldedToken](#NativeShieldedToken): a single token type issued and burned by the contract.
  - [NativeShieldedTokenFamily](#NativeShieldedTokenFamily): many token types, keyed by domain, under one contract.
  - [NativeShieldedTokenCore](#NativeShieldedTokenCore): the shared core behind the two flavors; not composed directly.
- **Extensions**
  - [NativeShieldedTokenPublicSupply](#NativeShieldedTokenPublicSupply): on-chain minted and burned totals for a `NativeShieldedToken`.
  - [NativeShieldedTokenFamilyPublicSupply](#NativeShieldedTokenFamilyPublicSupply): per-domain on-chain totals for a `NativeShieldedTokenFamily`.
  - [NativeShieldedTokenPublicSupplyCore](#NativeShieldedTokenPublicSupplyCore): the shared core behind the two supply extensions; not composed directly.
  - [NativeShieldedTokenDerivedNonce](#NativeShieldedTokenDerivedNonce): mint coin nonces derived from a counter.
- **Preset**
  - [ZOwnableNativeShieldedToken](#ZOwnableNativeShieldedToken): a single token whose `ZOwnablePK` owner mints and burns, with a public minted total.

These modules export no structs or enums of their own. Coins are the standard library's `ShieldedCoinInfo`
(a `nonce`, `color`, and `value`) and `QualifiedShieldedCoinInfo` (the same plus the Merkle-tree index `mt_index`
of a coin the contract holds).

#### _mint [toc] [#NativeShieldedToken-_mint]
#### [!toc] [#NativeShieldedToken-_mint]
<APIItemCompact
  circuitSig='_mint(
    recipient: ZswapCoinPublicKey,
    amount: Uint<64>,
    nonce: Bytes<32>
  ) → ShieldedCoinInfo'
  kind="circuit"
  complexity="k=14, rows=10473"
  modulePrefix="NativeShieldedToken"
  stackParams="true"
>
  Mints `amount` of the token to `recipient` using the caller-supplied `nonce`, and returns the new coin's info.

  The caller is responsible for nonce uniqueness: reusing a nonce for the same (value, recipient) produces a
  duplicate commitment, which the ledger rejects. With a secret, random nonce the mint is recipient-private;
  for mints without a caller-managed nonce, compose `NativeShieldedTokenDerivedNonce` and pass its `_deriveNonce()` output.

  The returned coin info is the only copy available to the recipient, so callers should deliver it out of band;
  wallets cannot detect contract-minted coins by scanning the chain.

  Puts the coin color, the amount, and the coin commitment on the ledger. The recipient and the nonce are not posted.

  Requirements:

  * Contract is initialized.
  * `recipient` is not the zero key.
</APIItemCompact>

#### _mintToSelf [toc] [#NativeShieldedToken-_mintToSelf]

#### _burn [toc] [#NativeShieldedToken-_burn]
#### [!toc] [#NativeShieldedToken-_burn]
<APIItemCompact
  circuitSig='_burn(
    coin: ShieldedCoinInfo,
    amount: Uint<128>,
    refundTo: ZswapCoinPublicKey
  ) → Maybe<ShieldedCoinInfo>'
  kind="circuit"
  complexity="k=16, rows=41492"
  modulePrefix="NativeShieldedToken"
  stackParams="true"
>
  Burns `amount` from `coin`, a coin provided within the current transaction (for example paid in by the
  caller's wallet), and routes the remaining change to `refundTo`.

  Returns the refund coin created for `refundTo` as `some`, or `none` if the coin was burned in full.
  To burn the coin in full, pass `coin.value` as `amount`; `refundTo` is inert in that case but must still be
  supplied and non-zero. For coins the contract already holds, use `_burnFromSelf` instead.

  The returned refund coin info is the only copy available to `refundTo`; callers should deliver it out of band.

  Puts the spent coin's nullifier and the output commitments on the ledger. The amount is not posted; a change
  output reveals that the burn was partial.

  Requirements:

  * Contract is initialized.
  * `coin.color` is this contract's token color.
  * `amount` is less than or equal to `coin.value`.
  * `refundTo` is not the zero key (the zero key is the burn address; a zero `refundTo` would burn the change as well).
</APIItemCompact>

The shared, domain-parameterized core behind `NativeShieldedToken` and `NativeShieldedTokenFamily`.
It is not meant to be composed directly: compose one of the two flavors instead.
Every token operation takes the `domain` separator as a parameter, and the assertion messages use the generic
`NativeShieldedToken:` prefix.

---

A native shielded token with a single shielded owner. Only the owner mints (to a coin public key, with a
caller-supplied nonce) and burns (a coin the owner's wallet pays into the transaction). Minted amounts are
counted on-chain; burned amounts are not, so burns stay amount-private.

The preset composes `ZOwnablePK` (the owner commitment), `NativeShieldedToken` (one token color), and
`NativeShieldedTokenPublicSupply` (the minted total). Implementing contracts call `initialize` from their
constructor and must not import the composed modules directly.

#### [!toc] [#ZOwnableNativeShieldedToken-initialize]
<APIItemCompact
  circuitSig='initialize(

    instanceSalt: Bytes<32>,
    tokenDomain: Bytes<32>,
    name_: Opaque<"string">,

    decimals_: Uint<8>
  ) → []'
  kind="circuit"
  modulePrefix="ZOwnableNativeShieldedToken"
  stackParams="true"
>
  Sets the owner and the token's domain and metadata.

  Call from the implementing contract's constructor only. It writes sealed fields, so implementing contracts
  must not expose it as a post-deploy circuit.

  `ownerId` must be `_computeOwnerId(pk, secretNonce)` for the coin public key the owner's wallet will supply

  usable owner and no recovery.

  Requirements:

  * `ownerId` is not zero.
  * `instanceSalt` is not zero.

  Burns `amount` of `coin`, paid into the transaction by the caller's wallet, and refunds the rest to `refundTo`.
