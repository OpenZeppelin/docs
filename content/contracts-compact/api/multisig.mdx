This page provides the full API for the Multisig modules.

<Callout type='info'>
  For an overview of the modules, read the [Multisig guide](../multisig).
</Callout>

The page covers the following modules:

- [Signer](#Signer): the registry of who may approve and how many approvals are required, generic over the signer identity type.
- [ProposalManager](#ProposalManager): the lifecycle of transfer proposals, independent of the token kind.
- [ShieldedTreasury](#ShieldedTreasury): holds one shielded coin per token color on the ledger and sends from it.
- [ShieldedTreasuryStateless](#ShieldedTreasuryStateless): receives and sends shielded coins without keeping any ledger state.
- [UnshieldedTreasury](#UnshieldedTreasury): holds unshielded tokens with a tracked per-color balance.
- [ForwarderPrivate](#ForwarderPrivate): forwards shielded deposits to a parent stored as a commitment.
- [ForwarderShielded](#ForwarderShielded): forwards shielded deposits to a public parent in the same transaction.
- [ForwarderUnshielded](#ForwarderUnshielded): forwards unshielded deposits to a public parent in the same transaction.

The module never resolves the caller; the consuming contract passes an identity in.

#### initialize [toc] [#Signer-initialize]
#### [!toc] [#Signer-initialize]
<APIItemCompact
  circuitSig='initialize<#n>(signers: Vector<n, T>, thresh: Uint<8>) → []'
  kind="circuit"
  id="Signer-initialize"
>
  Registers each entry of `signers` and sets the threshold to `thresh`.
  If used, it MUST only be called from the contract's constructor; a contract may instead configure signers through its own gated flow with [_addSigner](#Signer-_addSigner) and [_setThreshold](#Signer-_setThreshold).
  The signer identities and the threshold are disclosed to the ledger.

  Requirements:

  * Contract is not initialized.
  * `thresh` is not zero.
  * `thresh` does not exceed the number of `signers`.
  * `signers` contains no duplicates.
</APIItemCompact>

#### assertThresholdMet [toc] [#Signer-assertThresholdMet]
#### [!toc] [#Signer-assertThresholdMet]
<APIItemCompact
  circuitSig='assertThresholdMet(approvalCount: Uint<8>) → []'
  kind="circuit"
  complexity="k=9, rows=54"
  modulePrefix="Signer"
>
  Asserts that `approvalCount` meets the threshold.
  The count is supplied by the consuming contract and compared against the threshold only; the registry is never consulted,
  so the contract's approval accounting must itself be gated by [assertSigner](#Signer-assertSigner) and count distinct signers.
  The count is not bounded by `_signerCount`, so approvals collected before a signer was removed still count.

  Requirements:

  * The threshold is set (not zero).
  * `approvalCount` is greater than or equal to the threshold.
</APIItemCompact>

  kind="circuit"

  Sets the approval threshold without checking it against the signer count. `newThreshold` is disclosed.

#### _createProposal [toc] [#ProposalManager-_createProposal]
#### [!toc] [#ProposalManager-_createProposal]
<APIItemCompact
  circuitSig='_createProposal(
    to: Recipient,
    color: Bytes<32>,
    amount: Uint<128>
  ) → Uint<64>'
  kind="circuit"
  modulePrefix="ProposalManager"
  stackParams="true"
>
  Increments the proposal counter, stores a new `Active` proposal under the new id, and returns the id.
  The whole proposal (recipient, color, amount, status) is disclosed to the ledger.
  The counter is incremented and read back as the map key, so concurrent creations against the same state conflict.

  The recipient is not validated beyond being well-typed: a kind the execution rail cannot accept creates a proposal that stays `Active` until cancelled,
  and an unspendable address is accepted.

  Access control is NOT enforced. The consuming contract must gate this behind its own authorization policy.

  Requirements:

  * `amount` is greater than zero.
</APIItemCompact>

#### _deposit [toc] [#ShieldedTreasury-_deposit]
#### [!toc] [#ShieldedTreasury-_deposit]
<APIItemCompact
  circuitSig='_deposit(coin: ShieldedCoinInfo) → []'
  kind="circuit"
  modulePrefix="ShieldedTreasury"
>
  Claims `coin` with `receiveShielded`, then merges it into the stored coin of the same color (`mergeCoinImmediate`) or inserts it when the color is new,
  and adds its value to the received total.
  The coin and the updated total are disclosed to the ledger.
  Zero-value deposits are permitted: on a new color the zero coin occupies that color's slot until a later deposit merges into it.

  Access control is NOT enforced. The consuming contract must gate this behind its own authorization policy.

  Requirements:

  * The received total for `coin.color` plus `coin.value` does not overflow `Uint<128>`.
</APIItemCompact>

#### _send [toc] [#ShieldedTreasury-_send]
#### [!toc] [#ShieldedTreasury-_send]
<APIItemCompact
  circuitSig='_send(
    recipient: Either<ZswapCoinPublicKey, ContractAddress>,
    color: Bytes<32>,
    amount: Uint<128>
  ) → ShieldedSendResult'
  kind="circuit"
  modulePrefix="ShieldedTreasury"
  stackParams="true"
>
  Looks up the stored coin for `color`, sends `amount` of it to `recipient` with `sendShielded`, and adds `amount` to the sent total.
  Any change is routed back to the contract as a self-owned output and retained in `_coins` for the next spend;
  when the send leaves no change, the color's entry is removed.
  The color, recipient, amount, and retained change coin are disclosed to the ledger.

  The returned `ShieldedSendResult` carries the sent and change coins in plaintext; returning it from an entry point, writing it to the ledger,
  or passing it to another contract discloses them.
  The change coin belongs to the treasury and must not be spent again by the caller.

  Access control is NOT enforced. The consuming contract must gate this behind its own authorization policy.

  Requirements:

  * A coin of `color` exists in the treasury.
  * The stored coin's value is greater than or equal to `amount`.
  * The sent total for `color` plus `amount` does not overflow `Uint<128>`.
</APIItemCompact>

<APIItemCompact

  kind="circuit"
  modulePrefix="ShieldedTreasuryStateless"
  stackParams="true"

  Sends `amount` of the caller-supplied `coin` to `recipient` with `sendShielded` and returns the result untouched.
  The coin, recipient, and amount are disclosed.
  Any change is routed back to the contract as a self-owned output and returned in `result.change` as a live, spendable coin:

  Consuming it in-circuit is safe; returning it from an entry point, writing it to the ledger, or passing it to another contract publishes those coins,

<APIItemCompact

  ) → ShieldedSendResult'
  kind="circuit"
  complexity="k=15, rows=23937"
  modulePrefix="ForwarderPrivate"

  Sends `value` of a previously deposited `coin` to `parent` with `sendShielded`, after checking that `(parent, opSecret)` hashes to the stored commitment.
