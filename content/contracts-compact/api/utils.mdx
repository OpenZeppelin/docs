#### zeroAccount [toc] [#Utils-zeroAccount]
#### [!toc] [#Utils-zeroAccount]
<APIItemCompact
  circuitSig='zeroAccount() → Either<Bytes<32>, ContractAddress>'
  kind="pure"
  modulePrefix="Utils"
>
  Returns the canonical zero `Either<Bytes<32>, ContractAddress>` value: the left variant (`Bytes<32>`) set to zero.
  Used as the sentinel for mint and burn operations (a zero `from` signals a mint, a zero `to` signals a burn)
  and for cleared approvals.

  The left variant is returned so that `isTargetZero` compares against `default<Bytes<32>>`
  and so that the value does not trigger contract-address guards.
</APIItemCompact>

#### computeAccountId [toc] [#Utils-computeAccountId]
#### [!toc] [#Utils-computeAccountId]
<APIItemCompact
  circuitSig='computeAccountId(secretKey: Bytes<32>) → Bytes<32>'
  kind="pure"
  modulePrefix="Utils"
>
  Computes an account identifier without on-chain state, allowing a user to derive
  their identity commitment before submitting an operation.

  Derivation: `accountId = persistentHash(secretKey)`, with no domain-separation tag.

  The absence of a tag is deliberate. The identifier is global by design: the same key material yields the same
  identity in every module deriving one, so a user who wishes to carry one identity across modules can.
  Modules wanting a per-deployment, unlinkable identity should not use this circuit.

  Not for private derivation. This returns an identifier, not a secret, and the construction is untagged.
  A circuit deriving a private value from a secret must use its own domain-separation tag.

  <Callout type='warn'>
    `secretKey` is a sensitive secret. Never log or persist it in plaintext (browser devtools, application logs,
    analytics pipelines, or any observable side-channel). Prefer offline storage or secure enclaves (HSMs,
    air-gapped devices, encrypted vaults) over hot storage. Generate it with `crypto.getRandomValues()` or equivalent;
    weak or predictable keys can be brute-forced to reveal the identity. Treat key loss as identity loss: a lost key
    cannot be recovered. Avoid evaluating this circuit in untrusted environments (an unverified browser extension,
    a compromised runtime, or a shared machine) where the key may be exposed to a malicious observer.
  </Callout>

  Requirements:

  * `secretKey` is a 32-byte cryptographically secure random value.
</APIItemCompact>
