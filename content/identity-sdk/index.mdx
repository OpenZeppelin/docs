title: Identity SDK
description: Viem-native TypeScript SDK for the ONCHAINID identity stack

ONCHAINID gives a person, company, asset or agent an on-chain identity contract that holds keys (ERC-734) and signed claims about it from trusted issuers (ERC-735). In this version each identity is an ERC-7579 modular smart account deployed by an `IdentityFactory`, so it can be driven with ERC-4337 user operations as well as plain transactions.

`@openzeppelin/identity-sdk` covers what an integrator needs on top of [viem](https://viem.sh):

- address prediction and deployment through the `IdentityFactory`;
- `toIdentity`, which turns a deployed identity into a viem `SmartAccount` for any ERC-4337 bundler;
- call encoders and read actions for keys, claims, wallet linking, modules and the ERC-734 execution queue;
- EIP-712 signing helpers for claims and `LinkAccount` messages;
- passkey keys through ERC-7913 verifiers;
- the vendored ONCHAINID ABIs.

<Callout type="warn">
  The SDK is in early development. Its public API is unstable through the ongoing ONCHAINID audit cycle (0.x semver).
</Callout>

## Installation

```bash
npm install @openzeppelin/identity-sdk viem
```

Requires Node.js 22 or later.

`toIdentity` is built on [`@openzeppelin-accounts/sdk`](/accounts/sdk), declared as an optional peer dependency. That package is not on npm yet; until it is, consumers who use `toIdentity` need to provide it themselves. Only `toIdentity` uses it; everything else (encoders, reads, signing, addressing, ABIs) depends on viem alone. The package root re-exports `toIdentity`, so `@openzeppelin-accounts/sdk` must currently be resolvable for an `import ... from '@openzeppelin/identity-sdk'` to load.

## Quickstart

Resolve a wallet's identity, then add a key to it through a bundler:

```ts
import { createPublicClient, http } from 'viem';
import { privateKeyToAccount } from 'viem/accounts';
import { createBundlerClient } from 'viem/account-abstraction';
import { baseSepolia } from 'viem/chains';
import {
  formatEvmV1,
  getIdentity,
  identityActions,
  KeyPurposes,
  KeyTypes,
  toIdentity,
} from '@openzeppelin/identity-sdk';

const client = createPublicClient({ chain: baseSepolia, transport: http() });
const owner = privateKeyToAccount(process.env.OWNER_KEY as `0x${string}`);

// Resolve the owner's wallet to its identity.
const factory = '0x...'; // IdentityFactory address
const identity = await getIdentity(client, {
  factory,
  account: formatEvmV1({ chainId: baseSepolia.id, address: owner.address }),
});

// Drive the identity as an ERC-4337 account and add an ACTION key.
const account = await toIdentity(client, { address: identity, signer: owner });
const bundler = createBundlerClient({ account, client, transport: http(process.env.BUNDLER_URL) }).extend(
  identityActions(),
);
const hash = await bundler.addKey({
  identity,
  signerData: '0x...', // 20-byte address of the new key
  purpose: KeyPurposes.ACTION,
  keyType: KeyTypes.ECDSA,
});
await bundler.waitForUserOperationReceipt({ hash });
```
