AI coding assistants can write TRON contracts quickly, but they learned mostly from Ethereum code. Left alone, they reach for `parseEther`, trust `transfer`'s return value, and mix up TRON's address formats. OpenZeppelin's MCP server and dev tools keep the assistant on audited library code and TRON-correct defaults.

This guide connects the tools to your assistant, then rebuilds the vault from [Build a USDT vault on TRON with Hardhat](/tron-contracts/guide-usdt-vault) by prompting instead of typing. Read that tutorial first if you haven't. You need to know what correct output looks like before you can review an agent's output.

The generator tools return Solidity source as text. They don't write files, compile or deploy anything. In hosts that support [MCP Apps](https://modelcontextprotocol.io/extensions/apps/overview), such as Claude and Cursor, each tool also opens an interactive Wizard panel where you can change options and send the result back to the agent.

Every generated contract imports from `@openzeppelin/tron-contracts`, uses TRON names (`TRC20`, `TIP712`), and targets Solidity 0.8.26. For example, `tron-custom` with `--name UsdtVault --access ownable` returns:

```solidity
// SPDX-License-Identifier: MIT
// Compatible with OpenZeppelin TRON Contracts ^5.6.0
pragma solidity ^0.8.26;

import {Ownable} from "@openzeppelin/tron-contracts/access/Ownable.sol";

contract UsdtVault is Ownable {
    constructor(address initialOwner) Ownable(initialOwner) {}
}
```

## Install and connect

The local server runs with `npx`. `@openzeppelin/contracts-mcp` declares no `engines` constraint, so there is no enforced minimum; use an active Node.js LTS. If you are also following the [vault tutorial](/tron-contracts/guide-usdt-vault), `@openzeppelin/hardhat-tron` does require Node.js 22 or newer.

### Claude Code

```bash title="Shell"
claude mcp add OpenZeppelinContracts -- npx -y @openzeppelin/contracts-mcp
```

### Claude Desktop, Cursor and Windsurf

Add this to the client's MCP configuration. In Claude Desktop, go to **Settings > Developer > Edit Config**. In Cursor, go to **Settings > Cursor Settings > Tools & Integrations > MCP Tools > New MCP Server**.

```json title="MCP configuration"
{
  "mcpServers": {
    "OpenZeppelinContracts": {
      "command": "npx",
      "args": ["-y", "@openzeppelin/contracts-mcp"]
    }
  }
}
```

### VS Code

```json title=".vscode/mcp.json"
{
  "servers": {
    "OpenZeppelinContracts": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@openzeppelin/contracts-mcp"]
    }
  }
}
```

## Walkthrough: build the USDT vault with an agent

### 1. Describe what you want

Start with a prompt that states the TRON facts the agent might otherwise get wrong:

```text title="Prompt"
Build a TRC-4626 vault on TRON over USDT-TRON using OpenZeppelin Contracts for TRON 5.6.
- Shares: "USDT Vault Share" / "vUSDT", decimals offset 6.
- Entry and exit fee in basis points, capped at 5%, paid to a treasury set at deploy time.
- Pay every outbound transfer with SafeTRC20.safeTransferChecked: USDT-TRON's transfer returns false on success.
- USDT has 6 decimals. Never use ether units.
Use the OpenZeppelin MCP tools for the contract, and Hardhat 2 with @openzeppelin/hardhat-tron for the project.
```

## Review what the agent built

An agent's output is a draft. You are responsible for what you deploy.

**Library first.** Prefer contracts the MCP generates, or imports from `@openzeppelin/tron-contracts`, over code the agent writes. The library is audited (TRON Foundation audit #01, covering the library and the upgradeable variant). Code the agent writes is not. Keep any custom code small and review it line by line.

**Check every change against this TVM list.**

| Check | What to look for |
| --- | --- |
| Amounts | No `ether`, `gwei` or `parseEther`. TRX and USDT-TRON use 6 decimals. |
| Outbound transfers | `SafeTRC20.safeTransferChecked` for tokens you don't control. Not for rebasing or reflection tokens. |
| Addresses | Contracts get 20-byte hex. Base58 `T…` stays off-chain. No 21-byte `0x41…` inside `bytes` payloads. |
| Compiler | Solidity 0.8.26, `evmVersion: cancun`, compiled with tron-solc. |
| Toolchain | Hardhat 2 with `@openzeppelin/hardhat-tron`. No Ethereum Upgrades plugins. |
| Time | No block-count assumptions from Ethereum. TRON produces a block every 3 seconds. |
| Keys | No private keys in code, config or chat. The TRE dev key appears only in the `tre` network. |

**Run the tests yourself.** Read the test file before you trust a green run. Agents sometimes weaken an assertion to make a test pass.

**Before mainnet,** follow the usual path: tests, a review, and an audit for anything that holds user funds. See the [Security Center](https://contracts.openzeppelin.com/security).

## Troubleshooting

**The assistant doesn't list the `tron-*` tools.** Restart the client after you edit its MCP configuration. Check that `npx -y @openzeppelin/contracts-mcp` runs in a terminal. Make sure the package is 0.6.5 or later: earlier versions have no TRON tools.

**The assistant writes Ethereum code anyway.** Name the tool in your prompt ("use `tron-custom`"), and repeat the TRON facts from [step 1](#1-describe-what-you-want).

**Generated code imports `@openzeppelin/contracts`.** That's the Ethereum library. Ask the agent to regenerate with a `tron-*` tool, or replace the import paths with `@openzeppelin/tron-contracts` and the `ERC` names with `TRC`.

**`npx hardhat test` can't connect to Docker.** Start Docker. The tests need a local TRE container. See the [tutorial](/tron-contracts/guide-usdt-vault#test-on-a-local-tron-node).
